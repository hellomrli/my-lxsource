# 验证规则与报告

my-lxsource 区分“取得播放地址”和“地址返回真实音频”。只有完整的三层检查通过，源组合才进入构建候选。

## 三层检查

| 层 | 检查 | 能说明什么 |
|---|---|---|
| L1 | 脚本加载、声明平台与音质、返回非空合法 HTTP URL | 该脚本可以取得一个地址 |
| L2 | HTTP 200 或 206，逐跳检查重定向 | 地址可连接，排除死链 |
| L3 | 读取音频前缀、排除错误 MIME、识别格式，检查 FLAC 和位深 | 检查时返回的是符合要求的音频 |

默认检查 `wy/tx/kw/kg/mg` 五个平台和 `128k/320k/flac/flac24bit` 四种音质。每个平台使用《晴天》和《海阔天空》两个不同歌手或曲库的样本。

报告记录每首歌的结果；未声明的组合记为跳过。组合至少一首 L3 通过才成为候选，报告中的 `1/2` 只表示一首样本通过，不代表整个曲库可用。

## 字节与 HEAD 宿主

字节宿主通过有界探针或流式 fetch 最多读取 4096 字节，然后取消请求。它能识别真实 FLAC 和位深，即使 CDN 的 MIME 写成 `audio/mpeg` 或 `application/octet-stream`。

HEAD 宿主检查连通性并排除明确的 HTML、JSON 和视频。对于普通音质，二进制或缺失 MIME、不支持 HEAD 的 405/501 被视为无法确定；最终播放由播放器处理。它不能证明无损格式，因此只声明普通音质。

## 整合包发布条件

构建调用最终脚本自己的 `musicUrl`，实际经过子源选择、回退与播放校验，再独立 GET 检查返回地址的音频字节。字节与 HEAD 两种宿主分别验收。

每个实际声明的平台和音质都必须至少有一首样本通过。初始化成功、HEAD 成功或返回 URL 都不能替代独立音频检查。失败时保留上次成功发布的脚本。

## 报告与时间

[health.md](../reports/health.md) 展示源组合和每曲目明细；[playback.md](../reports/playback.md) 展示最终包的两种宿主结果及产物 SHA256。播放 URL 不写入健康报告，避免长期公开临时签名。

上游服务、曲库和签名地址随时间变化。报告时间与通过率应共同用于判断当前产物，而非当作持续可用承诺。
