# 整合脚本与隔离原理

LX 自定义音源负责 `musicUrl`，将歌曲标识换成播放地址；搜索由客户端 SDK 完成。my-lxsource 把经过验证的子源嵌入一个脚本，统一初始化、调度与播放校验。

## 选择与嵌入

只有同一份源码实测通过的平台和音质被声明。重复 SHA256 的脚本合并覆盖范围后只加载、嵌入一次；重复脚本和初始化失败的候选不占 `maxSources` 名额。

同品牌按版本号选择最新可用脚本。品牌比较会归一化 Pro、Plus、手机版、桌面版等后缀；最新版本初始化失败时回退到下一可用版本。

`maxSourceBytes` 限制单个源码，`maxEmbedBytes` 限制全部嵌入源码。每份源码在产物中出现两次，因此构建按源码预算限制客户端 2 MiB 产物体积。超预算源仍可巡检，但不嵌入。

元数据解析兼容 LF、CRLF 和 CR，读取过程不改写缓存源码或 SHA256。

## 作用域与静态加载

每个子源绑定独立的 `globalThis/window/self/global/lx` 作用域，异步回调仍绑定原子源。加载器将子源转换为静态函数，不依赖运行时 `eval` 或 `new Function`。

巡检和构建在禁用字符串代码生成的环境中验证；依赖动态执行才能初始化或播放的子源不计为可用。允许动态执行的宿主保留子源显式使用 eval/Function 时的作用域兼容。

## 超时与回退

默认取地址预算为 12 秒，音频校验为 8 秒，完整回退链为 45 秒。失败只降低对应平台与音质的优先级，默认冷却 30 秒；成功或冷却到期恢复。单首歌曲失败不会禁用整个子源，也不会取消其他并发歌曲。初始化失败仍禁用本次加载的该子源。

## 巡检进程边界

客户端作用域隔离用于兼容和避免串扰。同步死循环无法在同一个 JavaScript 线程内抢占，真实巡检为每个源使用独立 bubblewrap OS 进程。

沙箱不挂载 home 或项目，不继承宿主凭据，隔离 PID 和网络，并限制 CPU、内存、计时器和 IPC。`node:vm` 模拟 LX API，OS 沙箱承担进程隔离。

网络通过可信父进程的 HTTP 通道。DNS 地址在连接时固定并检查，私网、回环、保留地址、云元数据和重定向到这些地址被拒绝。请求时限覆盖 DNS、响应头和响应体；普通 API 最大 1 MiB，源码最大 2 MiB，音频只读取前缀。

OS 沙箱仍依赖宿主内核，实际巡检适合不带敏感凭据的临时 runner。源码固定到 commit，并逐步核对 SHA256、runId 与报告时间。
